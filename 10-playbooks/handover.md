# Client Project Handover

## Purpose

This playbook covers the steps required to complete a website project professionally and give the client everything they need to own, operate and move their website.

A complete handover includes:

1. Ownership and access
2. A technical recovery package
3. A client operating guide

## 1. Complete and Approve the Project

- [ ] Complete final testing
- [ ] Record any known limitations
- [ ] Obtain written client approval
- [ ] Collect the final payment
- [ ] Confirm the defect-warranty period and its end date
- [ ] Explain that future changes and maintenance are priced separately

## 2. Confirm Ownership and Access

Where possible, the client should own and pay for the services their website depends on.

- [ ] Confirm the client owns the domain registrar account
- [ ] Confirm the client owns the Cloudways account, or document the managed-hosting arrangement
- [ ] Give the client a WordPress Site Owner account
- [ ] Provide access to analytics, Search Console, email delivery and other connected services
- [ ] List all third-party plugins, subscriptions and renewal responsibilities
- [ ] Make sure everyone uses individual credentials and two-factor authentication
- [ ] Make sure recovery email addresses belong to the client
- [ ] Transfer custom work after final payment, subject to the agreed contract terms

If the website remains in an agency-owned Cloudways account, the agreement must explain what the hosting fee includes, who handles updates and backups, what happens if payment stops, and how the client can leave.

Cloudways distinguishes between account owners and team members. Only the account owner can perform certain account-level actions, including managing team members. See [Cloudways team-member guidance](https://support.cloudways.com/en/articles/5119753-how-to-create-and-update-team-members).

## 3. Create the Technical Handover Package

Create a dated full-site backup containing:

- [ ] WordPress files
- [ ] Custom theme and site-specific plugin source
- [ ] Uploads and media
- [ ] Database export
- [ ] Basic restoration or migration notes

A complete WordPress backup requires both the website files and the database. See the [WordPress backup documentation](https://developer.wordpress.org/advanced-administration/security/backup/) and [Cloudways application-backup instructions](https://support.cloudways.com/en/articles/5123346-how-to-download-the-backup-of-your-application).

Store the archive securely somewhere the client controls. Do not send it as an ordinary email attachment because it may contain personal or sensitive information.

## 4. Deliver the Client Website Guide

Provide a short, client-specific guide as an editable document and PDF. Add a brief screen recording or training session where useful.

Cover:

- How to log in securely
- The difference between Content Editor and Site Owner accounts
- How to edit text, images, patterns and testimonials
- How to use revisions
- Recommended image sizes and preparation
- How a Site Owner can add a page
- What is intentionally locked and why
- How backups and updates are handled
- Who renews the domain, hosting and licences
- What to do if the website is unavailable, a form stops working, access is lost or a security issue is suspected
- How to request support and what work is chargeable

Never put passwords in the guide. Share them through a password manager or another secure method.

## 5. Close the Project

- [ ] Securely deliver the backup and client guide
- [ ] Confirm the client can access all required accounts and files
- [ ] Deliver the training session, if included
- [ ] Start the agreed defect-warranty period
- [ ] Offer an optional maintenance agreement
- [ ] Record the final handover date and warranty end date

The client should finish the process with genuine independence. Ongoing support should be a clearly defined service, not a dependency created by missing access or documentation.
